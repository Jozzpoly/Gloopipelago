# M4a implementation boundary notes

M4a implementation must begin on a fresh branch from the exact x40 product lineage, not by promoting the audit branch or treating audit probes as runtime authority.

Carry forward only the canonical living-world audit receipt and the predeclared M4 contract. Audit-only probe tools remain evidence apparatus on the audit branch unless a specific probe is intentionally promoted into maintained qualification tooling.

The first implementation strategy should prefer default-off ecological configuration inside `Simulation` so that historical default behavior remains exactly testable. M4a may then instantiate explicit founder/start-resource counts and deterministic habitat definitions without duplicating the whole core.

Before any Owner candidate, prove both:

1. old/default `Simulation` remains exact under protected M0/M1/M2a process tests;
2. the new M4a configuration satisfies its own intentional-divergence, long-horizon, local-adaptation and x40 gates.
